# SETUP: от нуля до публикации в Дзене

Пошаговый порядок. Шаги 1–3 делаете вы (нужны деньги и ваши аккаунты), остальное уже подготовлено в проекте.

Время: примерно один вечер на шаги 1–4, ещё 30 минут на шаги 5–7.

---

## Шаг 1. Купить домен

**Требования Дзена (официальные):**
- домен должен быть **латиницей** — IDN-домены (кириллица вроде `пример.рф`) Дзен не принимает;
- домен RSS-ленты обязан совпадать с доменом подключённого сайта.

**Кандидаты, которые по DNS не отвечали на момент проверки** (вероятно, свободны — подтвердить в регистраторе):

- `ponjatno-pro.ru` — рабочий вариант в этом проекте
- `delorazum.ru`
- `zhivem-umno.ru`
- `dela-v-porjadke.ru`

Заняты (проверено): `umnodom.ru`, `delno.ru`, `praktika-doma.ru`, `delaem-sami.ru`, `delovoy-dom.ru`, `umnyi-dom.ru`, `pro-delo.ru`, `svoi-put.ru`.

**Где покупать:** reg.ru, timeweb, beget — цена `.ru` обычно 200–1000 ₽/год. Берите сразу на 2 года: продление иногда дороже первого года.

После покупки:
1. Впишите домен в `site.config.json` → `site.base_url` (например `https://ponjatno-pro.ru`, без слэша в конце).
2. Пересоберите сайт: `python build.py --clean`.

## Шаг 2. Хостинг: GitHub Pages (бесплатно)

Почему GitHub Pages: статический сайт, 0 ₽/мес, автоматический деплой по push, бесплатный HTTPS.

1. Создайте **публичный** репозиторий на github.com (например `ponjatno-pro`).
2. Загрузите проект:
   ```bash
   git init
   git add .
   git commit -m "init: сайт-источник для Дзена"
   git branch -M main
   git remote add origin https://github.com/<ваш-логин>/ponjatno-pro.git
   git push -u origin main
   ```
3. В репозитории: **Settings → Pages → Source: GitHub Actions**. Workflow `.github/workflows/pages.yml` уже лежит в проекте и соберёт сайт сам.
4. **Settings → Pages → Custom domain**: впишите домен. GitHub создаст файл `CNAME` (проект тоже его генерирует при сборке).
5. DNS у регистратора:

   | Тип | Имя | Значение |
   |---|---|---|
   | A | `@` | `185.199.108.153` |
   | A | `@` | `185.199.109.153` |
   | A | `@` | `185.199.110.153` |
   | A | `@` | `185.199.111.153` |
   | CNAME | `www` | `<ваш-логин>.github.io` |

6. Дождитесь DNS (от 15 минут до нескольких часов), включите **Enforce HTTPS**.

**Альтернатива — Cloudflare Pages:** тоже бесплатно, репозиторий может быть приватным, скорость в РФ обычно выше. Настройка: подключить репозиторий, build command `python build.py`, output directory `public`. Плюс: их CDN отдаёт статику быстрее. Минус: интерфейс на английском.

**Проверка:** откройте `https://ваш-домен/feed.xml` — должна открыться лента (не 404).

**Можно сначала без домена.** Чтобы проверить сайт на `username.github.io/repo`, впишите в `site.base_url` полный путь, например `https://username.github.io/ponjatno-pro`. Генератор добавит префикс во все внутренние ссылки, `robots.txt`, sitemap и RSS, а `CNAME` создавать не будет. Когда купите домен — поменяйте `base_url` на `https://домен` и пересоберите: больше ничего менять не нужно.

## Шаг 3. Яндекс.Вебмастер: сайт в поиске

Это и есть «добавить сайт в поиск Яндекса» — без этого поисковый трафик не появится.

1. [webmaster.yandex.ru](https://webmaster.yandex.ru) → **Добавить сайт**.
2. Подтвердите права. Самый простой способ — HTML-файл: положите его в `static/root/` и пересоберите сайт; генератор скопирует файл в корень.
3. После подтверждения: **Индексирование → Файлы Sitemap** → добавьте `https://ваш-домен/sitemap.xml`.
4. Проверьте `robots.txt` (генерируется автоматически, лента разрешена).
5. Через 1–2 недели проверьте «Страницы в поиске»: должны появиться статьи.

## Шаг 4. Яндекс.Метрика: статистика

1. [metrika.yandex.ru](https://metrika.yandex.ru) → **Добавить счётчик** → укажите домен, включите вебвизор по желанию.
2. Скопируйте **номер счётчика** и впишите в `site.config.json` → `analytics.yandex_metrika_id` (число, без кавычек).
3. Пересоберите: `python build.py --clean` и запушьте.

Код счётчика генератор вставит на все страницы автоматически.

## Шаг 5. РСЯ: реклама Яндекса на сайте

Порядок важен: сначала трафик, потом заявка.

1. Сайт должен иметь «сложившуюся аудиторию» — формального порога нет, на практике смотрят на живой поисковый трафик. Реалистично: 300–1000 визитов в месяц.
2. Подайте заявку в [Рекламную сеть Яндекса](https://yandex.ru/adv/products/rsya) (через кабинет Яндекс.Директ → «Мои сайты»).
3. Дождитесь модерации. При отказе из-за «недостаточной аудитории» повторная подача возможна через 30 дней.
4. Получите код блока: скопируйте `ads/rsy.example.html` в `ads/rsy.html` и вставьте в него выданный Яндексом код.
5. В `site.config.json` поставьте `"ads": { "enabled": true }`.
6. Пересоберите и запушьте — блоки появятся в статьях и на главной.

**Важно:** пока модерация не пройдена, `ads.enabled` должен быть `false`, иначе на страницах будет пустое место.

Про «рекламу в поиске» в другом смысле: если вы хотите **платно продвигать** сайт через Яндекс.Директ (промостраницы, поиск) — это отдельный бюджет и отдельная задача, к доходу от РСЯ она отношения не имеет. Для нового сайта без товара это обычно убыточно: сначала контент и органический трафик.

## Шаг 6. Дзен: подключение RSS

**Порядок действий в Студии:**

1. Заведите канал на [dzen.ru](https://dzen.ru) (если ещё нет).
2. **Наберите 10 подписчиков** — без этого сайт к каналу не подключить (требование Дзена).
3. Студия → **Настройки → Свой сайт** → добавьте домен.
4. Подтвердите права на сайт через HTML-файл или метатег (файл кладите в `static/root/`).
5. **Настроить трансляцию материалов сайта в Дзен** → укажите `https://ваш-домен/feed.xml`.
6. Отправьте ленту на проверку. Статус — в разделе **Свой сайт**.

**Что проверяют (и что мы уже соблюдаем):**

| Требование | Статус в проекте |
|---|---|
| RSS 2.0, валидный XML | ✅ `scripts/validate.py` проверяет |
| Минимум 10 материалов при первой подаче | ✅ 14 статей готовы |
| Не менее 3 публикаций за последний месяц | ✅ все свежие |
| ЧПУ-адреса без UTM и параметров | ✅ `/рубрика/slug/` |
| Полный текст в `content:encoded` | ✅ |
| Обложка в `enclosure`, минимум 700 px | ✅ 1200×630 |
| `robots.txt` не запрещает ленту | ✅ |
| Домен латиницей, совпадает с доменом сайта | зависит от вашего домена |
| Оригинальный контент, не рерайт | зависит от текстов |

**Если отказали:**
- «RSS недоступна или технические ошибки» — исправьте и подавайте повторно **в любое время**.
- «Содержимое не соответствует требованиям» — повторная подача **через 6 месяцев**. Поэтому перед подачей пройдите чек-лист ниже.

**Чек-лист перед подачей:**
```bash
python build.py --clean
python scripts/validate.py      # должно быть 0 ошибок
```
И откройте `https://ваш-домен/feed.xml` в браузере — лента должна открываться без ошибок.

## Шаг 7. Отчёты в Telegram

### 7.1 Создать бота

1. В Telegram найдите **@BotFather** → `/newbot`.
2. Имя бота (любое) и username, заканчивающийся на `bot` (например `ponjatno_report_bot`).
3. BotFather пришлёт **токен** вида `123456789:AAE...` — это `TG_BOT_TOKEN`.

### 7.2 Узнать chat_id

1. Напишите своему боту любое сообщение (иначе он не сможет вам писать).
2. Откройте в браузере:
   `https://api.telegram.org/bot<ТОКЕН>/getUpdates`
3. Найдите `"chat":{"id":123456789,...}` — это `TG_CHAT_ID`.
   Альтернатива: написать боту **@userinfobot** — он покажет ваш id.

### 7.3 Прописать в проект

Создайте файл `.env` рядом с `build.py`:

```
TG_BOT_TOKEN=123456789:AAE...
TG_CHAT_ID=123456789
```

Проверка без отправки:
```bash
python scripts/tg_report.py --dry-run
```

Отправка:
```bash
python scripts/tg_report.py
```

Если отчёт не приходит: проверьте, что вы написали боту первым (боты не могут начинать диалог), и что токен скопирован без пробелов.

## Шаг 8. Расписание

### Вариант А: планировщик DSH (если работаете в нём)

Одна задача на отчёты, вторая — на написание статей. Пример правила: каждый день в 10:00 по Москве.

### Вариант Б: Планировщик задач Windows

1. «Планировщик заданий» → **Создать задачу**.
2. Действие: запуск программы
   `C:\...\python.exe` с аргументами `scripts\tg_report.py`
   и рабочей папкой `F:\ProjectDeepSeek\dzen-portal`.
3. Триггер: ежедневно в удобное время.

### Вариант В: GitHub Actions (отчёт без вашего компьютера)

Добавьте в репозиторий секреты `TG_BOT_TOKEN` и `TG_CHAT_ID` (Settings → Secrets and variables → Actions) и запускайте `scripts/tg_report.py` по расписанию через отдельный workflow.

## Шаг 9. Регламент работы

1. **Темп:** 2–3 статьи в неделю. Чаще — падает качество, реже — Дзен хуже разгоняет канал.
2. **Перед публикацией:** `build.py` → `validate.py` → push.
3. **Раз в месяц:** отчёт в Telegram + проверка статистики в Метрике и Студии.
4. **Раз в квартал:** обновить устаревшие цены и сроки в старых статьях (они индексируются и живут годами).
5. **Налоги:** для монетизации Дзена оформите самозанятость — Дзен предлагает договор с физлицом, самозанятым, ИП или юрлицом.
6. **С 10 000 подписчиков:** канал нужно зарегистрировать в перечне Роскомнадзора, иначе реклама на нём запрещена.
